# 要求まとめ: TODO の親子関係とマインドマップ表示

## 背景と目的

現状の TODO アプリはフラットな 1 階層のリストしか持たない。
タスクを「マインドマップのように」表示し、中心から枝分かれする形で整理できるようにしたい。
そのために、**タスクに親子関係を持たせる**ことが前提になる。

最終的なゴールは、思考を整理しながら TODO を分解・再配置できる作業画面を得ること。

## スコープ

### バックエンド

1. TODO が親タスクを持てるようにする（1 タスク = 親は 0 or 1、子は複数）。
2. 同じ親の中での**並び順**を保持する（マインドマップの上下の並びが安定するため）。
3. 親子関係を**変更する**（別の親にぶら下げ替える／並び順を変える）API を用意する。
4. 循環参照（自分の子孫を自分の親にする等）を防ぐ。

### フロントエンド

1. 既存の TODO 一覧画面は**そのまま残す**。
2. それに加えて、**マインドマップ表示**を新しいビューとして追加する。
3. マインドマップは**左から右へ子が伸びる**、トーナメント表のようなレイアウトにする。
4. マインドマップ上でキーボードだけでタスクを操作できるようにする。

## キーボード操作の要求

左→右レイアウトに合わせ、**矢印キーの向きと画面上の移動方向を一致させる**。

| キー | 動作 |
| --- | --- |
| `→` | 子ノードへ移動（階層を下る） |
| `←` | 親ノードへ移動（階層を上る） |
| `↑` | ひとつ上の兄弟へ移動 |
| `↓` | ひとつ下の兄弟へ移動 |
| `F2` | 選択中タスクのタイトルを編集開始 |
| `Enter` | 兄弟タスクを新規追加（編集中は確定） |
| `Tab` | 子タスクを新規追加 |
| `Delete` | 選択中タスクを削除 |
| `Esc` | 編集キャンセル |

`←` / `→` を階層移動、`↑` / `↓` を兄弟移動に割り当てる点は確認済み。

## 非スコープ（今回はやらない）

- 複数ユーザー / 認証 / 同時編集
- マウスドラッグによるノードの移動（キーボード操作を先に完成させる）
- ノードの折りたたみ状態のサーバー永続化（クライアント内の一時状態にとどめる）
- キャンバスのパン・ズーム（必要になったら別タスクで）
- 期限・タグ・優先度などの新しい属性

## 用語

- **ノード** — マインドマップ上に描画された 1 つの TODO。
- **ルート** — 親を持たない TODO。複数存在してよい（森構造）。
- **兄弟** — 同じ親を持つ TODO の集合。並び順を持つ。
- **子孫** — ある TODO から親子リンクを辿って到達できるすべての TODO。
